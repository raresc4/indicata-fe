# Indicata frontend

- Indicata builds internal _planul de învățământ_ evaluation reports indicator by indicator for Bachelor, Master, and Doctorate programs; only the Doctorate template exists so far. Sources come from university URL crawls, Google search, or uploads. Each generated or edited piece must retain its version and source attribution; a later, separate step unifies/restyles the indicators into a human-readable report.
- This is the Angular frontend. The separate, unfinished FastAPI/SQLModel backend is at `../server`; consult its `AGENTS.md` and schemas when integrating, rather than assuming endpoints exist.
- `src/main.ts` bootstraps `src/app/app.ts` via `app.config.ts`. `app.routes.ts` redirects `''` to `/login` and lazy-loads the login page; `app.html` is just `<router-outlet />`. The `shell`, auth guard, and interceptors are not built yet. Do not mistake the README for the intended product design.

## Architecture for new work

- Keep app code organized by type in `src/app/`: `components/` (one folder per component, with `.ts`, external `.html`, optional `.scss`), `guards/`, `interceptors/`, `mocks/`, `models/`, `pipes/`, `services/`, plus the existing app entry files. Always keep component HTML in a separate `.html` file via `templateUrl`, never an inline `template`; resolve external paths relative to their `.ts` file. The only exception is inline `template` in `.spec.ts` test host components. Do not introduce feature-level source trees elsewhere.
- Routed screens end in `-page`; the app shell is `shell`. Lazy-load every page with `loadComponent` in `app.routes.ts`. Auth routes live outside the shell; all other routes are inside it behind the auth guard.
- Standalone components only; do not explicitly set `standalone: true` or `changeDetection` (defaults in Angular 22). Use `inject()`, `input()` and `output()` instead of their decorators, and `model()` for two-way bindings. Put host bindings/listeners in the decorator's `host` object, not `@HostBinding`/`@HostListener`. Keep components small and templates declarative; extract repeated long Tailwind class sets into reusable components.
- Use `@if`/`@for`/`@switch`, not structural control-flow directives; use `class`/`style` bindings instead of `ngClass`/`ngStyle`. Import only the needed pipes/directives, not `CommonModule`. Do not call unavailable globals such as `new Date()` in templates. Use `NgOptimizedImage` for static images (not inline base64 images).
- Use TypeScript interfaces in flat `models/*.model.ts` files mirroring backend schemas; name flat pipes/mocks after their contents. Write strict code even though `tsconfig.json` does not yet enable `strict`: avoid `any` (use `unknown` for uncertain data) and non-null assertions; infer obvious types and prefer `readonly`, `const`, and explicit public return types.
- No NgRx or other state library. Each backend resource gets a typed `*-api.service.ts` wrapping `HttpClient` and returning observables; each screen area gets a `*-state.service.ts` with a private `BehaviorSubject`, exposed through `asObservable()`, that calls the API service. `HttpClient` is provided via `provideHttpClient()` in `app.config.ts`; API services read the base URL from `src/environments/environment.ts` (`apiBaseUrl`, default `http://localhost:8000`) rather than hardcoding hosts. The error interceptor/snackbar is still not built, so components surface request failures directly for now. Emit new state copies rather than mutating existing objects. Components consume state with the `async` pipe; if a manual subscription is unavoidable, use `takeUntilDestroyed`. Prefer reactive forms over template-driven forms; do not replace shared screen state with signals or Signal Forms.
- Keep services single-purpose; new singleton services use `@Service()` (`providedIn: 'root'` by default in Angular 22) and `inject()`, not constructor injection. Auth interceptor adds the token; error interceptor reports failures via Material snackbar.

## UI and language

- Start new screens from the relevant `src/design/<screen>/{web,mobile}/` references and reuse existing UI/shell patterns. Use Tailwind v4 for mobile-first layout, spacing, sizing, and simple UI; use Angular Material 3 for dialogs, tables, steppers, form fields, menus, and snackbars. Keep component SCSS for cases Tailwind cannot express, such as complex animations.
- Preserve design tokens: `src/styles.css` maps `--mat-sys-*` colors plus `--font-sans` (Inter) and `--font-serif` (Newsreader) into Tailwind via `@theme inline`, so use token-backed utilities (`bg-primary`, `text-on-surface-variant`, `border-outline-variant`, `font-serif`, etc.); do not hardcode template/component hex colors or style Material internals with utilities. Material tokens come from `material-theme.scss`; the design references' own hardcoded palettes are not tokens. Ask before changing tokens or introducing new visual patterns. Semantic `success`/`warning` colors (with `on-*` and `-container` variants) are defined as fixed values in the `@theme inline` block because the Material system palette has none; use their token utilities (`bg-success`, `text-warning`, `success-container`, etc.) for status and diff styling rather than hardcoding hex.
- All user-facing copy must use Transloco keys, grouped by feature with matching `ro.json`/`en.json` keys. The language toggle belongs only in Settings; persist the choice in `localStorage`. Transloco and these locale files are not set up yet: ask before adding the required dependency.
- Password-strength scoring uses `@zxcvbn-ts/core` with the `@zxcvbn-ts/language-common` dictionary, wrapped in `services/password-strength.service.ts`. The dictionary is ~420kB, so only import it inside lazy-loaded routes; never pull this service into the initial bundle.
- Rich text editing uses TipTap (`@tiptap/core`, `@tiptap/pm`, `@tiptap/starter-kit`, pinned exact). It is heavy, so import it only from the indicators draft-view/editor service modules reachable through the lazy `/project/:projectId/indicators` route; never pull it into the initial bundle. The `IndicatorContent` model round-trips to TipTap JSON in `services/indicator-editor-model.ts` (custom `citation`/`missingDoc` nodes and `unsourced`/`humanEdited` marks); keep editor-library specifics inside `IndicatorDraftView` and these services.
- Every UI change must meet WCAG AA and pass AXE checks, including keyboard focus management, contrast, and appropriate ARIA attributes.

## Constraints and checks

- Never add code comments, JSDoc, or TODO markers, including in newly generated code. Make only the requested change; ask before adding dependencies or changing design tokens. If a requirement is ambiguous, ask one concise question before coding.
- After any substantial code change or change that may need documentation, reread `AGENTS.md` and update it if the guidance is incomplete or outdated.
- `npm run start` serves the app; `npm run build` is the production build; `npm run test` runs Angular's Vitest unit-test builder. Run the build after changes and check tests where relevant. `ng lint`/`npm run lint` are **not configured** (no ESLint dependency or lint target); do not claim lint passed or install a linter without asking.
- Format with the repo's `.prettierrc` via `npx prettier --write <changed files>`. `prettier-plugin-tailwindcss` is not installed/configured yet; ask before adding it. Do not change unrelated starter or user-owned files just to enforce these conventions.
